# Blue interface

Collections, Notes and Calendar share one native Liquid Glass tab bar. The root keeps it mounted when navigating into a collection or note or opening Blue. Native floating sheets cover it until dismissed. Blue is a separate native control immediately to the right of the bar and remains there while the chat is open.

Press feedback follows the control's shape. Circular controls use a circular highlight, and rows and menu actions use rounded corners.

Tapping Blue opens the voice surface first. A centered animated orb follows listening, speech and work. Status is available to VoiceOver. A short tone follows the first transmitted microphone packet. The bottom row offers text entry, microphone mute and a close button that switches to chat. Spoken replies appear in the chat. GPT-Live 1 speaks with Marin, with guidance for a youthful adult feminine tone and Spain pronunciation in Spanish. For a clear task, Blue briefly says what it is doing and then reports the outcome returned by the tool. GPT-Live delegates when a request needs a library tool. The dictation setting applies to text input. In chat, the microphone records a draft and the waveform opens voice. A draft replaces the waveform with Send. The native text field grows to four lines and scrolls beyond that. Enter sends and clears the composer immediately. Stop replaces Send while Blue works.

Blue uses iOS thin material over the current view down to the bottom edge, including behind the keyboard. The native tab bar stays in front of the backdrop. The transcript fades separately from the backdrop. A tap on the transcript dismisses the keyboard. The close and reset controls stay above the scrolling transcript. Reset clears the conversation and retains the unsent draft. The assistant uses the saved provider configuration on opening. Settings validates a new key against the provider catalog. Provider failures are shown when an actual request fails.

Collections have a fixed back chevron and ellipsis. The centered name, item count and sort/filter control scroll with the list. The Filters sheet places filter controls above Sort by, with each sort field shown as a direct choice. Compact property glyphs wrap on the right of record names and expose their meaning through VoiceOver. In record details, centered rows give every property tile the same width, icon size and spacing. Captions use a reserved two-line area. Record property buttons use a quick press animation and a brief randomized particle burst with Reduce Motion off. Favorites use stars, likes use hearts and watched can use a filled eye. Numeric fields open a number picker. An empty numeric field shows a small centered dot in the list and detail. Other optional empty values stay hidden.

Holding a collection or note opens a native context menu, lifts the row and dims the whole window. These menus offer Pin and Delete, with Icon or cover below Pin for collections. Holding a record gives haptic feedback and opens its detail sheet. In a collection, Select items enters selection mode. Swiping to delete a record enters the same mode with that record checked. Filters stay available while the add button is hidden. The glass bar shows the selection count and a trash action that opens a confirmation. The upper close button exits selection. Delete labels and their trash icons use red. Swipe right to pin a collection or note, or mark a record as a favorite. Swipe left to enter record deletion selection or request deletion of a collection or note. A centered confirmation with a close button explains that deleting is irreversible. Editors, filters and property controls use opaque native floating sheets with a leading glass chevron and trailing actions. Scrollable editors measure their contents for their initial height. Drag the header up to expand or down to dismiss.

Notes open on the navigation stack. The first line is the title and uses larger bold type. The body is plain text with line breaks. Both autosave once the note has a title. The editor keeps an untitled note as a draft during the session. The plus opens the current section’s editor directly. The checkmark in an existing record sheet appears only after an edit. Existing Markdown syntax stays in the stored text. The calendar updates the inline agenda for the selected day. The top plus opens an editor with the selected day and a preset time. The checkmark saves a new event or changes to an existing event. The checkmark is available immediately on new events. A blank name saves as the localized “Event”. The compact event sheet has a centered title and a leading name field. In the remaining rows, labels sit on the left and values on the right. Hold an agenda row to delete the event. Date and Time each open a native wheel picker directly underneath the row. Only one picker is open at a time. Date components follow the chosen language, and time uses the 24-hour format. Future events schedule a system alarm and a local notification. Past events can be created and edited as history.

The Theme section in Settings uses a native segmented control for System, Light and Dark. Language uses a menu picker at the bottom of Settings. App-owned strings use the English and Spanish catalog. The user's content stays unchanged when switching language.

## Covers, menus, recurrence and settings

Collection and note long-press actions use native context menus. iOS lifts the selected row and dims the entire window, including the persistent tab bar. Ordinary row taps again use the shared rounded press highlight. The collection menu puts Icon or cover immediately below Pin, with the same action available from the collection header menu.

The optional collection image is a small rounded square beside the collection name and a centered square above its name on the collection screen. The cover editor offers Icon, Photo and AI. The guided AI flow follows the themes, editable subject, style, four previews and explicit save pattern demonstrated in [YouTube Music's official tutorial](https://www.youtube.com/shorts/v_mXC63sxt0). Covers remain local after selection and are included in exports and folder copies.

Event editing has only name, time, date, repeat and notes. Repeat sits directly below the date and above notes, with a trailing localized summary and seven circular weekday buttons. Empty means Never. New events never infer recurrence. Every event row has a blue dot and a native trailing Delete swipe that opens the existing confirmation. Repeating entries represent a whole weekly series; deleting one removes that series.

Settings sections can be collapsed by their headers. Storage offers a native Files directory picker, saved-copy status, disconnect, import and export. iCloud Drive is the simplest shared Apple directory; third-party providers are available when their Files extension permits folder selection. No paid iCloud app entitlement or distribution account is required.

## Read-only collection rows and plain hold menus

Collection row properties are display-only; taps open the detail editor. Favorite changes also require opening the element. Library holds use a flat menu with a subtly enlarged, lighter row and a uniform dim outside it; no preview shadow or native context-menu lift is used. Heavy impact feedback marks a completed hold. Theme remains a segmented control with system, sun and moon symbols and localized accessibility labels.

Drive storage is optional. An account with only the previous file scope shows Enable Drive backups. Authorized accounts show save progress, a last-success time only after readback verification, Back up now and Open backup folder. Text explains that the encrypted copy and recovery key are stored separately in the user's Google account. No folder picker or plaintext automatic export is used.

## Distribution and diagnostics (17 November 2026)

TestFlight is the planned installation/update surface. App-owned UI does not need a weekly reinstall prompt. Apple beta feedback and crash diagnostics are the initial support path; no analytics SDK is added. Cloud backup is optional and separate from distribution.
