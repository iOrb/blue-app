# Google Drive connection and backup status

Blue needs its own Google OAuth client; Codex's Google Drive connection cannot provide credentials to the iOS app. Configure a Google Cloud project using the owner's account, enable Google Drive API, configure the OAuth consent screen and add the owner as a test user if the app is in testing. Create an iOS OAuth client with bundle ID `app.iorb.blue.ios`. Configure its client ID and reversed URL scheme in the project using Google's documented iOS flow. The iOS client ID is public application configuration, not a client secret. Never commit an OAuth client secret, access or refresh tokens, encryption keys, or user content.

Before enabling backup, implement sign-in and token refresh using Google's current native-app guidance, least-privilege `drive.file` authorization, app-created folder discovery or user-approved file access, encrypted full-snapshot creation, recoverable cross-device key management, safe conditional multi-device writes, download and full restore. A Google sign-in session alone is not recovery of the encryption key. Handle revoked permissions, offline writes, account changes and deleted files without replacing a newer or unreadable backup. Test real credentials and a separate test folder before touching user data. A folder created by a different OAuth client is not necessarily visible with `drive.file`.

Restoration refreshes expired credentials and verifies access; disconnect removes the device's credentials. It does not delete files or revoke the Google grant globally.
