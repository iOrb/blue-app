# Architecture

Blue is a SwiftUI application with local data and inference for iPhone, iOS 26 or later. There are no runtime third-party packages, remote inference services, telemetry, cloud inference, or network-fetched model weights. Explicit public lookups and automatic basic information for named public works use Wikipedia over HTTPS; only the public topic title leaves the app. Apple manages the availability of its on-device model.

## Persistence and values

`Domain` contains Sendable/Codable values: collections, records, notes and alarms. Legacy folder payloads are retained only for migration compatibility. Collection fields have stable semantic IDs and typed values. Notes and written record notes remain separate from ratings. Built-in labels reference string catalog keys; user text is preserved verbatim; model-created properties have editable English and Spanish labels.

`LibraryStore` owns a MainActor SwiftData context and a narrow observable library value. The versioned V1 schema stores independently keyed entity payloads, including an initialized marker. It fetches once on startup and saves only changed payloads in a transaction. A failed save rolls back without publishing the candidate state. Optimistic record/note revisions reject concurrent stale edits. The initialized marker prevents reseeding after deletions. The SwiftData entity schema remains V1. Payload/export version 2 flattens legacy folders, preserving collection IDs and moving grouped notes into equivalent collection records with their IDs, Markdown, revisions and favorites. Empty legacy folders become empty collections. No user data is reset. New production libraries start empty; starter templates are used only by test fixtures.

The current implementation encodes the in-memory entity set to identify changed payloads on each mutation. This favors simplicity and predictable rollback for personal libraries. Stress measurements determine when to replace this diff with explicitly tracked dirty IDs. Do not claim it is a paginated database. The bounded ten-step undo history excludes system alarm restoration. Collection queries above 500 records run on a cancellable detached task with a Sendable snapshot; stale results are not published. Small personal lists use the same pure query synchronously.

Export is UTF-8 JSON, `formatVersion: 2`, with ISO8601 dates, UUID references, semantic field IDs, tagged typed values, and Markdown separated from property values. Export is explicit through the system file picker. No import or cloud sync is included in this first version.

## Assistant

Requests use lightweight routing for explicit capture/schema commands and typed on-device classification for other requests. A fresh Foundation Models session receives only tools relevant to that request. Record reads are bounded; ambiguous matches cannot authorize edits. Captures create a record and any needed collection/schema in one store transaction. There are no predefined creation templates. The assistant can read/update records, create/adapt collections, change collection/property icons, add custom indicators, propose removal of populated fields, edit Markdown notes, and operate alarms. Destructive property changes carry a preview of the old/new schema and record revisions; confirmation rejects intervening edits.

Every request starts with mutations disabled. Recognized English/Spanish action words grant write permission; read questions and negations do not. Swift validates IDs, read revisions, field types, finite numbers, schemas and input limits. A request reserves at most one mutation before asynchronous work starts. Cancellation invalidates subsequent work and completed results from replaced requests are ignored. Production data actions render persisted state, while conversational/clarification text is displayed separately. Numeric edits must be grounded in the user's prompt, including Spanish decimal commas. Capture discards invented text/numbers and redundant title/Markdown properties. New factual fields must match user text or fetched source excerpts.

Wikipedia responses are untrusted reference data, never executable instructions. Public work/place categories or an explicit web request allow lookup; generic private captures do not. Source titles, excerpts and HTTPS links are stored separately from personal Markdown. Failed lookups do not fabricate facts or lose the capture. Results can include several similarly named works, so source links remain visible for review. No general-purpose browsing, shell execution or remote model tool is exposed.

A DEBUG simulator build can use a local Mac bridge when Apple's simulator model catalog is broken. `scripts/start-model-bridge.sh` compiles the same production model/tools, starts a transient launchd job bound to 127.0.0.1, and creates an ignored, mode-0600 per-run token. `scripts/run.sh` passes the token to the simulator process and stores a mode-0600 copy in that Debug simulator app’s development configuration, so Xcode relaunches can reconnect. No token is bundled or committed. The bridge executes against an ephemeral snapshot; the simulator validates the returned data and rejects a stale local snapshot before committing. The transport and configuration are compiled out of iPhone and Release builds. The Mac adapter rejects alarm actions; hardware alarms use iPhone AlarmKit. Stop the bridge with `launchctl remove app.iorb.blue.model-bridge`. This is real local inference, separate from the deterministic UI double.

A DEBUG-only deterministic assistant exercises exact-record reads/edits and custom hiking collection creation. It is selected only with `--test-assistant`, is labeled in Settings, and is compiled out of normal Release. Its results are never reported as evidence of real inference. The real-model integration test uses the production tools with a deterministic alarm adapter and is opt-in separately from CI.

## Alarms

`AlarmService` owns the system boundary through `AlarmScheduling`; tests inject a fake. Production uses AlarmKit authorization, schedules, cancellation and alarm updates. Fixed alarms retain an absolute instant; weekly alarms follow system wall-clock time and Calendar weekdays. Local enabled state is published only after system success. Store failures trigger best-effort compensation. System removals reconcile to disabled local records at foreground and from the update stream. On day/time-zone changes, fixed instants remain fixed and weekly alarm display values preserve their original wall-clock time in the new zone. Revoked authorization produces no enabled system IDs. No countdown UI is configured, so no Live Activity widget extension is required for this scope.

An expired or unavailable system alarm is not silently recreated. Authorization denial and scheduling failure remain visible. Physical-device verification is mandatory for delivery while locked, Focus/silent behavior, recurrence and timezone changes.

## Presentation and language

The two native bottom tabs retain navigation state. Library scope controls distinguish notes and collections; there is no folder UI. Saved notes open in rendered Markdown with an explicit edit control. The assistant sits above the tab bar. Collections use text rows with every populated property visible. Shared indicator controls render user-defined meanings with an emoji or SF Symbol and color in rows, detail and filters: pale gray when off, colored when on. Favorite filters use the star itself and toggle off with another tap. Query state belongs to collection IDs. Exact-record navigation preserves sort order and removes only filters that hide the requested record.

The `Localizer` observable reads String Catalog-generated resources from the selected language bundle. Changing language updates strings and locale formatting without replacing the root view or its navigation/editor state. User drafts remain unchanged. Unedited built-in demo text can resolve in the new language. Apple-controlled dialogs and keyboard text follow system language, as disclosed in Settings. The microphone explicitly requests microphone/speech permission, requires on-device speech recognition and writes the transcript into the editable chat input. Audio is not persisted. Leaving the view, changing language or backgrounding stops capture. Enter sends; tapping outside collapses the conversation without clearing its draft.
